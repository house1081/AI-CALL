# 计费联调测试步骤

> 后端默认 `http://127.0.0.1:8080`。若配置了 `freeswitch.callback-secret`，所有 `/api/callback/**` 请求需加 Header：`X-Callback-Secret: <密钥>`。

## 一、前置准备

1. 执行数据库脚本：`sql/init.sql` 或 `upgrade_v1.1.sql` + `upgrade_v1.2.sql`
2. 启动 Redis、MySQL，启动 `ai-call-server`
3. 确认测试商户（默认 seed 中 tenantId=1）：
   - `balance` 充足（如 100 元）
   - `sell_price` = 0.1200
   - 线路 `cost_price` = 0.0600

```sql
SELECT id, balance, sell_price, pending_deduct FROM tenant WHERE id=1;
SELECT id, cost_price FROM line WHERE status=1 LIMIT 1;
```

## 二、计费工具函数（本地单元）

`BillingUtil.ceilMinutes` 规则：

| 通话秒数 | 计费分钟 |
|---------|---------|
| 0 | 1 |
| 1~59 | 1 |
| 60 | 1 |
| 61 | 2 |
| 125 | 3 |

## 三、场景 A：未接通不计费

```bash
curl -X POST http://127.0.0.1:8080/api/callback/call-end ^
  -H "Content-Type: application/json" ^
  -d "{\"tenantId\":1,\"lineId\":1,\"customerPhone\":\"13800000001\",\"callDuration\":0,\"callStatus\":2}"
```

**预期**：`call_record` 新增一条，`deduct_amount=0`，`cost_amount=0`，`profit=0`，商户余额不变。

## 四、场景 B：短通话（1 分钟，无实时预扣）

```bash
curl -X POST http://127.0.0.1:8080/api/callback/call-end ^
  -H "Content-Type: application/json" ^
  -d "{\"tenantId\":1,\"lineId\":1,\"customerPhone\":\"13800000002\",\"callDuration\":30,\"callStatus\":1}"
```

**预期**（售价 0.12，成本 0.06）：

- `billed_minutes` = 1
- `deduct_amount` = 0.1200
- `cost_amount` = 0.0600
- `profit` = 0.0600
- 余额减少 0.12

## 五、场景 C：FreeSWITCH 会话流（推荐联调路径）

### 1. 接通开始

```bash
curl -X POST http://127.0.0.1:8080/api/callback/fs/call-start ^
  -H "Content-Type: application/json" ^
  -d "{\"tenantId\":1,\"lineId\":1,\"customerId\":1,\"customerPhone\":\"13800000003\",\"taskId\":1}"
```

记录返回的 `callRecordId`（示例：100）。

### 2. 第 1 分钟实时扣费

```bash
curl -X POST http://127.0.0.1:8080/api/callback/billing/deduct-minute ^
  -H "Content-Type: application/json" ^
  -d "{\"tenantId\":1,\"lineId\":1,\"callRecordId\":100,\"customerPhone\":\"13800000003\",\"elapsedSeconds\":60}"
```

**预期**：`success=true`，余额 -0.12，`call_record.prepaid_amount` = 0.12。

### 3. 第 2 分钟实时扣费

同上，`elapsedSeconds` 可填 120。`prepaid_amount` 累加至 0.24。

### 4. 挂断结算（125 秒 = 3 分钟）

```bash
curl -X POST http://127.0.0.1:8080/api/callback/fs/call-end ^
  -H "Content-Type: application/json" ^
  -d "{\"callRecordId\":100,\"callDuration\":125,\"callStatus\":1,\"level\":\"B\"}"
```

**预期**：

- 总应扣 = 3 × 0.12 = 0.36
- 已预扣 = 0.24
- 挂断时再扣差额 = 0.12
- `deduct_amount` = 0.36，`prepaid_amount` 在记录中保留历史值

### 5. 校验 SQL

```sql
SELECT id, call_duration, billed_minutes, prepaid_amount, deduct_amount, cost_amount, profit
FROM call_record WHERE id=100;

SELECT type, amount, balance_after, remark FROM balance_log
WHERE tenant_id=1 ORDER BY id DESC LIMIT 5;
```

## 六、场景 D：余额不足挂断

1. 将商户余额改为 0.10（不足 1 分钟售价 0.12）
2. 执行场景 C 的 `deduct-minute`
3. **预期**：`success=false`，`shouldHangup=true`，外呼任务 status=2（已暂停）

## 七、场景 E：待补扣与充值

1. 制造余额不足的长通话（结算时部分扣费）
2. 查看 `tenant.pending_deduct` > 0
3. 尝试启动任务应失败
4. 管理员审核充值后，`pending_deduct` 自动减少

```sql
SELECT balance, pending_deduct FROM tenant WHERE id=1;
```

## 十、FreeSWITCH 健康检查

```bash
curl http://127.0.0.1:8080/api/callback/fs/health
```

返回 `{"code":200,"data":{"status":"ok",...}}` 表示回调服务可用。

## 十一、生产对接提示

| 阶段 | 配置 |
|------|------|
| 模拟外呼 | `freeswitch.enabled: false`（默认） |
| 真实 FS | `freeswitch.enabled: true`，ESL 接线后 dialplan 回调 `call-start` / `deduct-minute` / `call-end` |
| 安全 | 设置 `freeswitch.callback-secret`，FS 脚本带 `X-Callback-Secret` |

Channel 变量建议：`call_record_id`、`tenant_id`、`line_id` 供 dialplan 拼回调 JSON。
