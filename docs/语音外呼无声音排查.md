# 语音外呼无声音排查

## 链路说明

```
外呼 originate → 客户摘机 → Java 轮询接通 → 大模型开场白文字 → TTS → ESL 播到通道
通话中：FunASR → POST /api/callback/fs/voice-turn → 大模型 → TTS → ESL 播报
```

## 1. 看 Java 日志（必查）

| 日志 | 含义 |
|------|------|
| `开始监听接通并播报 uuid=` | 外呼已下发，正在等摘机 |
| `接通自动建会话并播报` | 已检测到接通，将播开场白 |
| `ESL 播报` / `ESL HTTP 播报` | 已向 FS 下发播放命令 |
| `ESL 播报失败` | FS 无 TTS 模块或命令错误 |
| `监听超时未检测到接通` | 未摘机或 uuid 变量读不到 |

## 2. 配置检查 `application.yml`

```yaml
server:
  address: 0.0.0.0   # 必须，否则 FS 无法拉取 wav

ai-voice:
  playback-base-url: http://<运行Java的机器IP>:8081   # 不是 FS 的 IP，除非 Java 与 FS 同机
  tts-http-url: http://<TTS服务>/tts?text={text}      # 中文强烈建议配置

freeswitch:
  originate-application: "&echo"   # 与手动测试一致，保证双向音频
```

**已确认问题：** `speak::zh|default` + 中文话术在多数 FS 上**不会出声**，但 `bgapi` 仍返回 +OK。现改为优先 **HTTP 播放 wav**（Windows 可用系统 SAPI 合成中文）。

启动日志中看 `【语音】本机局域网 IP` 与 `playback-base-url` 是否一致。

## FS 在另一台机器、无法远程登录

**不需要 SSH 登录 FS。** Java 已通过 ESL（8021）控制 FS，语音流程为：

1. Java（本机）用 SAPI/HTTP 生成 wav，提供 `http://JavaIP:8081/uploads/tts/xxx.wav`
2. Java 经 ESL 在 FS 上执行：`curl -o /tmp/aicall-voice/xxx.wav http://JavaIP:8081/...`（`fs-fetch-via-esl: true`）
3. Java 经 ESL：`uuid_broadcast 通道uuid playback:///tmp/aicall-voice/xxx.wav`

**仍需网络：** FS 能访问 Java 的 **8081**（出站），Java 能访问 FS 的 **8021**（ESL）。请在 **Windows 防火墙** 放行入站 8081。

不能远程时你只需在本机：改 `playback-base-url` 为本机 IP、重启 Java、外呼测试。

## 3. FreeSWITCH 上测 TTS

```bash
fs_cli -x "module_exists mod_flite"
fs_cli -x "originate {origination_uuid=test-1}sofia/gateway/343543656/你的手机号 &park()"
# 另一终端
fs_cli -x "uuid_broadcast test-1 speak::en|flite|hello aleg"
```

若无声音，需安装 TTS 或改用 **HTTP TTS + playback**（配置 `tts-http-url`）。

## 4. 联调播报接口

通话保持中时：

```bash
curl -X POST http://127.0.0.1:8081/api/callback/fs/play-test \
  -H "Content-Type: application/json" \
  -d "{\"fsUuid\":\"通道uuid\",\"text\":\"您好，测试语音\"}"
```

## 5. 健康检查

```bash
curl http://127.0.0.1:8081/api/callback/fs/health
```

确认 `eslReachable: true`、`aiVoiceEnabled: true`。
